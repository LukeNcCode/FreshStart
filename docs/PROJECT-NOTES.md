# FreshStart · Win11 开荒工具

> 本文保留项目的完整开发历史、验收记录和已知边界。部分内容描述旧版本界面或已移除模块；最新产品说明以根目录 `README.md`、`docs/FEATURES.md` 和 `CHANGELOG.md` 为准。

一个把「刚装好的 Windows 11」调到顺手状态的桌面工具。**除明确标注为不可回滚的卸载/移除类操作外，写操作先备份、失败自动回滚、可撤销**；不采集、不上传任何数据。

> 0.30.1：修「取消不生效」的根因。① **根因**：读取 winget 输出用 `reader.EndOfStream` 作循环条件，它是**同步阻塞读**，导致 `RunRawAsync` 在第一个 `await` 之前就占住调用线程 —— 取消 token 还没注册、UI 线程被占用，于是「点了取消没反应，进程照样跑完」。改成 `ReadLineAsync` 循环后实测：`winget list` / `source update` 的取消从「完全无效（4388ms 跑完、`Canceled=false`）」变为「**242ms 中断、进程被杀、无残留**」。② 软件页取消后不再静默：区分「已取消 / 已回滚 / 失败」三态，并刷新已安装状态。③ 取消按钮点一次即变「取消中…」并禁用，避免重复点击无反馈。④ 无人值守此前传的是 `CancellationToken.None`，中途根本停不下来 → 新增「取消执行」按钮（已完成步骤保留、未执行跳过）。⑤ winget 自身更新与本地安装也能取消下载。

| 执行命令行 | `FreshStart.exe --execute=<方案.json> --yes`：无界面直接执行，写报告后按结果退出（0 成功 / 1 执行失败 / 2 缺少确认 / 3 方案无效或无步骤 / 4 异常）；`--unattended` 继续兼容 |

方案格式 v2（保存为 `.json` 后导入；编辑器的「导出方案」就是这个格式）：

```json
{
  "schemaVersion": 2,
  "name": "我的开荒方案",
  "description": "隐私优先 + 长路径 + 安装 Chrome + 卸载 QQ",
  "steps": [
    { "kind": "preset", "target": "privacy" },
    { "kind": "tuning", "target": "longpaths", "apply": true },
    { "kind": "ctxmenu", "apply": true },
    { "kind": "update", "target": "paused" },
    { "kind": "install", "target": "Google.Chrome", "name": "Google Chrome" },
    { "kind": "uninstall", "target": "QQ" },
    { "kind": "appx", "target": "Microsoft.ZuneMusic" }
  ]
}
```

| kind | target | 说明 |
|---|---|---|
| `preset` | `minimal` / `gaming` / `privacy` / `developer` | 应用整套预设 |
| `tuning` | 调控项 key | `apply: true/false` 表示应用/还原 |
| `ctxmenu` | — | `apply: true` 经典菜单，`false` 新版 |
| `update` | `normal` / `paused` / `extended` / `disabled` | Windows 更新 |
| `service` | 服务名 | `value`: `auto` / `manual` / `disabled` |
| `task` | 任务完整路径 | `apply`: `true` 启用 / `false` 禁用 |
| `dns` | 适配器名 | `value`: DNS 预设 key（`auto` / `aliyun` / `tencent` / `cloudflare` / `google`） |
| `power` | 电源计划 GUID | 切换电源方案 |
| `install` | winget ID | 可选 `name` 用于显示 |
| `uninstall` | 程序显示名 | 运行时按 ARP 列表匹配，匹配不到会跳过并记录 |
| `appx` | 包名/显示名 | 运行时模糊匹配当前用户 Appx；系统保护组件不会命中 |
| `cleanup` | 清理类别 key | 删除可再生成的缓存，不可回滚 |
| `driver` | 目标目录 | 导出第三方驱动包（只读系统） |
| `driver-install` | INF 文件或含 INF 的目录 | `pnputil /add-driver /install`，回滚时删除新发布驱动 |
| `driver-remove` | 已发布驱动包（oemXX.inf） | 先导出备份再删除，可回滚 |
| `firewall-profile` | `Domain` / `Private` / `Public` | `apply` 表示开启/关闭该配置文件 |
| `firewall-rule` | 规则显示名 | `value` 为 JSON：direction/action/protocol/port/program |
| `firewall-rule-remove` | 规则显示名 | 删除前读取定义，回滚时重建 |

旧的 v1 方案（`presets` + `options`）仍可读取，加载时自动迁移为 `steps`。方案只引用软件内已有的封装，**不执行任意脚本或外部命令**。

## 2. 技术栈与架构

- **.NET 8 + WPF**（不使用 WinUI 3）

```
│  ├─ FreshStart.App\        WPF 外壳、主题、对话框、Toast、单实例
```

### 写操作安全管线

```
用户确认（含本次首次写入的还原点选择）
  → 读取当前值
  → 备份到 %AppData%\FreshStart\backup\{timestamp}-{operation}\

  → 写入 + 读回校验
```

## 3. 安全与回滚说明

| 功能 | 风险 | 回滚方式 |
|---|---|---|
| 系统信息 | 安全 | 只读 |
| 快捷操作 | 安全 / 谨慎 | 无持久化修改；重启资源管理器会短暂黑屏 |
| 备份与回滚自检 | 安全 | 仅写 `HKCU\Software\FreshStart\SelfTest`，可用「撤销上一次操作」回滚 |
| 设置项 | 安全 | 写入 `settings.json`，可手动修改 |
| 右键菜单 / 风格 | 谨慎 | 注册表键/值快照；移除项进入隔离区可恢复；风格切换可切回 |
| 自启动 | 谨慎 / 高风险 | Run 的 StartupApproved、文件夹 `.disabled`、任务状态、服务启动类型均先快照 |
| Windows 更新 | 高风险 | 服务启动类型 + 策略值 + UpdateOrchestrator 任务状态快照，失败自动回滚 |
| Defender | 高风险 | Defender 偏好/排除项/自动恢复任务均先快照；篡改保护开启时拒绝修改 |
| 彻底移除 Defender 引擎 | 高风险 / **不可回滚** | 按 windows-defender-remover 13 删除服务/驱动、安全中心、SmartScreen、WebThreat、VBS/凭据保护、驱动阻止列表、系统缓解、任务/启动项/右键菜单/策略与安装目录；通过一次性 SYSTEM 计划任务执行；必须重启；可能导致 WSL2 / Hyper-V / 沙盒不可用、Windows 更新或商店组件需要修复 |
| 资源占用 | 安全 / 谨慎 | 只读曲线；结束进程不可撤销，必须二次确认 |
| 原生应用 | 谨慎 / 高风险 | 批量卸载前记录包清单；失败尝试重新注册，系统应用需二次确认 |
| 推荐软件 | 谨慎 | winget 安装；单个失败会记录并继续，已成功的软件保留，不自动回滚；重试只重试失败项 |
| winget 源策略 | 安全 | 只用微软官方源（0.28.1 起移除国内镜像）；若检测到旧版本遗留的镜像源会自动 `source reset` 迁回；软件页提供「更新源索引」刷新索引 |
| 推荐软件 | 谨慎 | winget 静默批量安装 + 官方直链兜底（0.30.0 起清单收敛为 7 条：解压缩 ×2 / 浏览器 ×2 / Everything / PotPlayer / OBS）；单个失败继续、已成功保留、不整批回滚 |
| 一键开荒 | 谨慎 | 批量注册表值快照；逐项校验，任一项失败整体回滚；可一键还原预设 |
| 隐私清理 | 谨慎 | 同样走注册表批量快照；策略项可能被系统忽略，页面显示实际值 |
| 磁盘空间 | 已移除（0.23.19） |
| 界面调优 | 谨慎 | 注册表批量快照，失败整体回滚；任务栏项需重启资源管理器 |
| 网络工具 | 谨慎 | DNS 切换与 IPv4 配置前快照原状态，失败/撤销时恢复；Ping 只读 |
| 电源管理 | 谨慎 / 安全 | 切换前快照原电源计划；内置方案不存在时用 `duplicatescheme` 创建再激活；快速启动写入 HiberbootEnabled 并备份 |
| 游戏优化 | 谨慎 | 注册表批量快照；HAGS 需要重启 |
| 服务与任务 | 高风险 | 服务启动类型与计划任务状态先备份；禁用运行中的服务重启后生效 |
| 软件卸载 | 高风险 / 不可回滚 | ARP 快照与审计记录；卸载调用程序自身命令，FreshStart 不保留安装包 |
| 驱动与备份 | 安全 | 只读取驱动包并复制到目标目录，不安装/修改驱动 |
| 配置导入导出 | 已移除（0.23.6） |
| 系统清理 | 谨慎 / 不可回滚 | 只删除可再生成的缓存；二次确认，占用文件自动跳过 |
| 硬件监控 | 已移除（用户反馈无实际用途） |
| 游戏滤镜 | 已移除（覆盖层在 PUBG 等游戏不可用） |
| 全局还原 | 高风险 | 自动记录 26 项注册表基准；还原前再次快照，失败回滚 |
| 执行中心 | 谨慎 / 高风险 | 配置阶段只记录方案；执行时只引用软件内已有封装；一次确认、逐步快照，单步失败跳过并记录；卸载/安装/Appx/OneDrive 步骤不可回滚，页面与报告会标出；命令行模式需 `--yes` 或 `--silent` 显式确认 |
| 防火墙 | 谨慎 / 高风险 | 关闭配置文件前记录三项状态；规则删除前读取定义，回滚时重建 |
| 驱动管理 | 高风险 | pnputil；删除前导出驱动备份，回滚时重新安装；可能需要重启，请先在虚拟机验证 |
| Windows 可选功能 | 高风险 | 启用/禁用前后读取功能状态，失败自动回滚；部分功能需要重启 |
| 安全中心托盘清理 | 谨慎 | 删除 `HKLM\...\Run\SecurityHealth` 并结束托盘进程；快照原值，可回滚；不影响 Defender 引擎 |
| 导航页 / 主页守护 / 离线开荒包 | 已移除（0.21.0 / 0.22.0） |

**关于「彻底移除 Defender 引擎」**：实现参考 [`ionuttbara/windows-defender-remover`](https://github.com/ionuttbara/windows-defender-remover) 13（CC BY-NC 4.0），注册表清单与文件删除范围来自该项目；FreshStart 只复用其步骤与数据，不捆绑或调用其 EXE / PowerRun，改用一次性 SYSTEM 计划任务执行。已知限制：24H2 上仍可能有 `MsMpEng.exe` / `MpDefenderCoreService.exe` 残留；删除系统组件后 Windows 更新/商店可能要求修复安装；不可自动回滚，建议先创建系统还原点。许可证副本见 `docs/third-party/windows-defender-remover-LICENSE.txt`。

**「备份与回滚自检」是什么？**

它只验证写入管线本身：在 HKCU 沙箱写一个时间戳，确认“读取当前值 → 生成备份 → 写入 → 读回校验 → 可回滚”整条链路正常。**它不是一键恢复，也不会修改系统设置或创建系统还原点。** 真正的撤销是设置页的「撤销上一次操作」，只回滚最近一次成功操作；“恢复到首次运行状态”的全局还原将在后续批次提供。

**还原点策略（按你的要求实现）**：

- 每次启动后的**第一次写入前**弹出自绘模态，询问是否为本次会话启用系统还原点；
- 三个选项：启用并继续 / 不启用，继续 / 取消；
- 选择只对本次进程有效，下次启动重新询问；
- 启用后**仅高风险操作**创建系统还原点（Windows 默认 24h 内只允许一次），普通与安全操作始终写 JSON 快照；
- 系统保护被关闭或被组策略禁用时会明确提示，并降级为仅 JSON 快照。

**撤销**：设置页「撤销上一次」使用内存中的操作栈 + 写入前快照回滚，并记录到审计历史。

## 4. 性能实测（Release 自包含单文件 + R2R）

## 6. 已知限制

1. **裁剪关闭**：WPF 不支持 trimming，采用自包含 + R2R；体积约 157MB。
2. **首次启动 831ms**：单文件原生库首次解包；后续冷启动约 470–510ms。
3. **游戏滤镜**：已移除；PUBG 等驱动级滤镜请使用 NVIDIA Freestyle / AMD Software，本项目不再维护覆盖层方案。
4. **还原点**：只在用户于首次写入弹窗中选择「开启」且操作风险为高时创建；普通操作仅 JSON 快照。
5. **UI 语言**：当前中文单语，文案已抽离为资源键，后续可加英文。
6. **Mica**：Win11 22H2+ 生效；Win10 / 远程桌面 / 禁用透明时自动降级为纯色窗口。
7. **开发清单**：Debug 构建使用 `app.dev.manifest`（asInvoker），Release 使用 `app.manifest`（requireAdministrator）。
8. **资源占用**：CPU/内存为 Win32 采样，磁盘/GPU 依赖 PDH；部分虚拟机或驱动没有 GPU Engine 计数器时显示“不可用”。结束进程不可撤销。
9. **原生应用**：只枚举当前用户；名称来自开始菜单显示名，可能随系统语言变化。框架/GUID 组件隐藏，无开始菜单入口的组件在“内部组件”里。卸载系统应用可能导致开始菜单/设置异常，恢复依赖安装目录仍然存在，不保证成功。
10. **推荐软件**：依赖 winget（App Installer）；已安装检测同时使用 `winget list` 的 ID 与注册表卸载项名称，支持 Chrome Beta / Firefox ESR 等渠道，但完全未登记到 ARP 的绿色版软件仍可能识别不到。部分安装器即使 `--silent` 仍会弹出自己的界面；内置 winget ID 可能随软件发布变化，可用自定义来源补充。
11. **一键开荒 / 隐私清理**：只修改 FreshStart 已知且在白名单内的注册表值；组策略、安全软件或 Windows 家庭版可能忽略部分策略项。预设不会修改服务、任务或文件。
12. **磁盘空间**：已移除（0.23.19）。
13. **界面调优**：任务栏对齐、时钟秒数、小组件/任务视图按钮等项目需要重启资源管理器或重新登录；部分改动可能被后续系统更新重置。
14. **网络工具**：只修改所选适配器的 IPv4 DNS；VPN/代理软件可能在连接时覆盖 DNS。Ping 使用 ICMP，可能被防火墙拦截。
15. **电源管理**：电源计划名称来自系统资源字符串，随系统语言变化；快速启动需要关机再开机生效（重启不生效）。
16. **全局还原**：已支持恢复到首次运行基准，覆盖 `TuningCatalog` 中的注册表调优项；不包含服务、计划任务、驱动与已卸载程序。
17. **游戏优化**：HAGS 需要重启；部分反作弊/驱动可能不兼容，关闭录制后 Win+G 仍可打开游戏栏。
18. **服务与任务**：只显示 Win32 服务（不含驱动）；禁用关键服务可能导致打印/网络/音频异常，页面会给出高风险确认。计划任务列表只包含非 Microsoft 的登录/开机任务。
19. **软件卸载**：卸载不可自动回滚；使用程序自带卸载命令，部分程序仍会弹出自己的界面或要求重启。没有卸载命令的绿色软件不会出现在列表中（后续可增加目录清理）。
20. **驱动与备份**：导出只复制驱动包，不创建系统还原点；`Get-WindowsDriver` 不可用时回退到 WMI 设备驱动列表。
21. **游戏滤镜**：已移除。
22. **执行中心**：配置阶段只记录方案，执行阶段按依赖顺序预检并运行，原生应用使用**内置的 41 项 Windows 11 出厂预装清单**，未安装的移除步骤执行时自动跳过；`Windows 安全中心`（`Microsoft.SecHealthUI`）为受保护组件，走强制卸载且不可回滚。开始与结束会发 Windows 通知。电源方案若目标不存在但属于 Windows 内置方案会创建副本；网络步骤按适配器匹配，改名时用 InterfaceIndex 回退；受保护服务自动跳过；Defender 操作受篡改保护限制；OneDrive 卸载不可回滚。执行中心**不执行任意脚本或外部命令**。默认单步失败跳过并继续，`"continueOnError": false` 可改为失败即整体回滚；卸载/安装/Appx/清理/驱动导出本身不可回滚，计划和报告会明确标出。命令行模式必须显式加 `--yes` 或 `--silent`。

23. **软件安装通道（0.34.9）**：winget 为主（manifest SHA256 + 安装包签名），**官方直链兜底** 5 条（Chrome / 7-Zip / Everything / Bandizip / PotPlayer）——winget 失败时改用厂商官方安装包（HTTPS 强制、下载到可信临时目录、512 MB 上限、可选 SHA256 + 强制 Authenticode 签名校验、登记好的静默参数、20 分钟超时、装完按 ARP 名称检测；无法确认按失败处理）。Firefox / OBS 没有稳定的国内直链，继续走 winget。Chocolatey 后端代码保留但不注册（`ChocolateyService`）。

24. **启动门槛 = 内置包版本**：`assets\winget` 内置 App Installer **1.29.380** + `windowsappruntimeinstall-x64.exe`（Windows App Runtime 1.8）+ 配套 `VCLibs.140.00 14.0.33519`（x64）与 `VCLibs.140.00.UWPDesktop 14.0.33728`（x64）。启动时若本机 winget **低于内置包版本** 或未检测到 → 前台阻塞窗口强制升级，不升级不进主界面；**版本更高则直接进入主页**，且安装前会比较版本、绝不用内置包降级。门槛随内置包自动跟随。

25. **旧系统缺少新版 VCLibs 时的处理（0.27.9+，winget 链路）**：App Installer 1.29 要求 `Microsoft.VCLibs.140.00 ≥ 14.0.33519` 与 `Microsoft.VCLibs.140.00.UWPDesktop ≥ 14.0.33728`。Windows App Runtime 安装器**不会**提升这两个 framework 包，`aka.ms` 上的 VCLibs 直链也仍是 14.0.33321（不够）。**离线解法已内置**：`assets\winget` 里带了 1.29.380 对应的两个 x64 VCLibs。仅当切回 winget 后端时才需要。

26. **自定义安装路径（winget 链路）**：软件页支持 `winget install --location`，仅对支持该参数的安装器生效（MSI / Inno / ZIP）。走**官方直链兜底**时不适用（直链用的是各厂商安装器的固定静默参数）。

27. **winget 门槛的联网例外（仅 winget 链路）**：切回 winget 后端时，启动门槛优先用 `assets\winget` 内置离线包；只有当内置包缺失/依赖不足且需要补 Windows App Runtime 时，才会从 `aka.ms/windowsappsdk/1.8/latest` 下载 `windowsappruntimeinstall-x64.exe` 并直接执行——这一步不是离线的。0.29.0-beta 默认不走这条链路。

28. **操作历史回滚的能力边界**：只回放快照里的注册表值、注册表键与服务启动类型；文件移动、计划任务、Appx、驱动、winget 等条目会跳过并计数，`Restored=0` 时按失败处理。回滚前会校验「备份目录在 `backup\` 之下」与 `snapshot.json` 的 SHA256，任一不满足即拒绝。

29. **不走统一写入口的路径**：系统清理、残留清理、历史回滚、安全中心托盘清理有二次确认，但不经过 `OperationRunner`，因此没有备份快照、不写 `operations.jsonl`；这些路径与 `OperationRunner` 共用同一把全局写锁（`IWriteLock`），所以与无人值守并发时会互斥而不是穿插执行。

> 架构与功能全貌见 `docs/OVERVIEW.md`，分层与文件职责见 `docs/ARCHITECTURE.md`。
